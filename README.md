# 减排归因与版本核算实验室（虚构演示）

一个零依赖的本地网页应用：把**活动数据、项目申报、核算因子与组织边界**放在同一张核算底稿上，
区分「实际排放变化」「基线估算」「可归属项目」，并在同一页面处理**重复申报、因子追溯更正与版本确认**。

> ⚠️ 站点、活动数据、因子与项目全部为虚构，仅用于演示方法与治理流程。
> 本工具**不声称符合任何未指定的认证、核查、披露或报告标准**，页面中任何数字都不构成排放声明。

## 运行

```bash
npm start            # 默认 http://127.0.0.1:3000
PORT=3111 DATA_DIR=/tmp/demo npm start   # 可选端口与状态目录
npm test             # 31 项核算与治理测试
```

要求 Node.js ≥ 20，无需 `npm install`。首次启动会在 `DATA_DIR/state.json` 生成虚构演示数据；
首页「数据」菜单可导出工作区 JSON、从 JSON 恢复、或重置回初始状态。

## 核算模型

对每个活动条目 `item`（基准活动 `a₀`、报告活动 `a₁`、关联项目集合、因子 `f₀/f₁`）：

```
E0 = Σ a₀·f₀          基准期实际排放
E1 = Σ a₁·f₁          报告期实际排放
D  = E0 − E1          实际变化（正数 = 减排）
```

项目效应用**反事实**构造，而不是把申报幅度直接相加：

```
aExp(item, S) = a₀ · Π_{i∈S∩linked}(1 − rᵢ)      S = 已实施项目集合，rᵢ = 项目申报幅度
E(S)          = Σ aExp(item, S) · f₁
B  = E(∅)     基线估算（项目全不实施）
P  = B − E(N) 项目总效应（全部项目联合实施）
O  = E(N) − E1 其它活动变化（项目未解释的部分，可正可负）
F  = E0 − B   因子更新效应（基准活动上的因子差）
```

恒等式 **D = P + O + F** 精确成立。归属方法只分配 `P`，不分配 `D`：

- **顺序优先**（`priority`）：按冻结的申报顺位依次扣减，顺序敏感；
- **比例分摊**（`proportional`）：按单独效应占比分摊 `P`，顺序无关；
- **Shapley**（`shapley`）：对 `v(S)=B−E(S)` 取所有组合的平均边际贡献，合计恰为 `P`；
- **保守归属**（`residual`）：只计入「其它项目均已实施」时的边际贡献，重叠部分单列为不归属。

单独效应 `sᵢ = B − E({i})`；乘性叠加下有 `Σsᵢ ≥ P`，差额即两个项目对同一变化的
**重复申报交互作用**。页面逐项展示重复贡献（按活动条目）、顺序穷举下的归属区间、
以及「因子更新 vs 真实活动变化」的两步分解（活动效应 `(a₀−a₁)·f₁` + 因子效应 `(f₀−f₁)·a₀`，两相之和等于 `D`）。

## 版本与治理

- **同版对照**：每个任务有基准指纹（基准版本、边界文本、基准活动、基准因子与边界重述记录）。
  指纹不同的两个任务不可直接对照；页面会列出差异，并提供「同步基准（rebase）」操作，保留报告期假设。
- **确认即冻结**：确认后任务写入内容哈希，活动、因子、项目与假设全部只读；旧任务不能修改已确认报告。
- **追溯更正**：基准因子更正、组织边界重述都会重建草稿并改变基准指纹，不影响既有报告。
- **更正留痕**：已确认报告只能撤回或由新草稿取代（取代会保留旧哈希）；所有写操作写入审计记录。
- **数据接入**：CSV（`itemId,period,activity`，仅 `report` 行）接入报告期活动，记录来源、行数、变更行数与行哈希；
  基准期变化必须经过追溯更正或边界重述流程。
- **乐观锁**：每次写操作携带 `expectedHash`，版本已变时返回 `409 STALE_BATCH` 并刷新页面。
